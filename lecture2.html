🌐 The OSI Reference Model

  • OSI = Open Systems Interconnection.
  • اتعمل بواسطة ISO (International Organisation for Standardisation) سنة 1984.
  • بيتعتبر دلوقتي الموديل المعماري الأساسي للاتصال بين الكمبيوترات (primary architectural model for inter-computer communications).
  • هو descriptive network scheme (مخطط وصفي للشبكة).
  • بيضمن توافق وتشغيل متبادل أكبر (compatibility and interoperability) بين أنواع تكنولوجيا الشبكات المختلفة.

بيوصف إزاي المعلومة بتتحرك من برنامج تطبيق (زي الـ spreadsheet) عبر وسيط الشبكة (زي السلك) لحد برنامج تطبيق تاني على شبكة تانية.

بيقسّم مشكلة نقل المعلومات لـ SEVEN مشاكل أصغر وأسهل = layering.

📋 ملخص مميزات الـ OSI Model (سلايد 6)

  1. يساعد الـ network administrators يحددوا الـ hardware والـ software المطلوبين لبناء شبكتهم.
  2. يشجّع مصنّعي الـ hardware يعملوا منتجات تتواصل مع بعض على الشبكة.
  3. أداة تعليمية لفهم عملية الاتصال بين مكونات الشبكة (teaching tool).
  4. يفصل الوظيفة المعقدة لمكونات أبسط.
  5. يسهّل الـ troubleshooting: تدوّر على المشكلة في الـ layer اللي بتسببها بدل ما تدوّر في الشبكة كلها.
📖 الكتاب بيزوّد: أسباب استخدام الـ OSI: (1) يقسّم عمليات الشبكة لعناصر أبسط، (2) يوحّد الـ interfaces ويخلّي المهندسين يتخصصوا في وظايف معينة، (3) يسهّل الـ modular engineering ويمنع تأثير تغيير على الباقي، (4) يضمن الـ interoperability، (5) يسرّع التطور والاختبار والـ troubleshooting.
و3 مبادئ اتطبقت لاختيار الـ 7 طبقات: layer تتعمل لما نحتاج abstraction مختلف · كل layer لها وظيفة محددة · وظيفة كل layer تتختار بحيث تؤدي لـ protocols قياسية دولياً.
وكل layer بتتصرف زي virtual machine بتقدّم خدمات للـ layer اللي فوقها وبتخبّي عنها تفاصيل التنفيذ.

    الطبقات العليا 7 · 6 · 5 🔝

    Application و Presentation و Session: بتتعامل مع المستخدم والداتا والجلسة. (⏱️ ٨ دقايق)

    Network Processes to Applications

    الـ layer اللي بتتعامل مع تطبيقات الشبكة:

    • File transfer, access, and management: تسمح لليوزر يدخل على ملفات في كمبيوتر بعيد، ويجيبها ويديرها.
    • Mail services: بتوفّر email forwarding and storage.
    • أمثلة السلايد: EmailWeb browsers
    ⚠️ فخ: الـ application layer مش الـ application نفسه! هي نافذة (window) للمستخدمين وعمليات التطبيقات عشان توصل لخدمات الشبكة، وبتوفّر الخدمات دي للمستخدم النهائي.
    📖 الكتاب: بتوفّر user interface للإرسال والاستقبال. بروتوكولاتها: HTTP (web browsing)FTP (file transfer)SMTP (sending email)DNS (domain name → IP address)

    كل application بتستخدم خدمة من الـ Transport layer. الـ PDU: data.

    Data Representation

    وظايفها التلاتة (احفظهم):

    1. Translation: الأنظمة بتتبادل character strings وأرقام، وكل كمبيوتر بيستخدم encoding مختلف. الـ presentation layer بتحوّل من صيغة تعتمد على المرسل لـ صيغة مشتركة (common format)، وفي الاستقبال من المشتركة لصيغة تعتمد على المستقبل.
    2. Encryption: للحفاظ على الخصوصية (privacy): بتحوّل المعلومة لشكل تاني وتبعته على الشبكة.
    3. Compression: بتقلّل عدد الـ bits اللي هتتبعت، وده مهم جداً في الـ multimedia (text, audio, video).
    📖 الكتاب: بتضمن إن الداتا بتتقدّم بصيغة يفهمها الـ application layer: encoding/decoding · compression/decompression · encryption/decryption.

    الشكل في السلايد: Encoded, encrypted, and compressed data + H6 (الـ header بتاعها).

    Interhost Communication

    • بتـتأسس (establish) وبتدير (manage / maintain) وبتنهي (terminate) الجلسات (sessions) بين جهازين بيتواصلوا.
    • وكمان بتعمل synchronization للتفاعل بين الأجهزة.
    • مثال السلايد: Client software (used for logging in)
    📖 الكتاب: مسؤولة عن network coordination بين تطبيقين منفصلين في جلسة.

    🎯 تدريب: ده شغل أنهي طبقة؟

    الطبقات 4 · 3 ⭐

    Transport و Network: مين بيوصّل الداتا وإزاي بتلاقي طريقها. (⏱️ ٩ دقايق)

    End-to-end Connections · PDU = Segments

    • بتاخد الداتا من الطبقة اللي فوقها وبتقسّمها لوحدات أصغر اسمها segments (segmentation)، وبتجمّعها تاني عند المستقبل (reassembly).
    • بتضمن نقل موثوق (reliability and flow control).
    • بتضمن إن الرسايل تتبعت بنفس ترتيبها ومن غير تكرار للداتا. المسؤولية الأساسية: تنقل الداتا كاملة.
    • اسمها end-to-end layer لأنها بتوفّر اتصال point-to-point بين المصدر والوجهة.
    • وظايفها: Segmentation and reassemblyFlow controlError controlConnection control
    • البروتوكولين: TCP (Transmission Control Protocol) و UDP (User Datagram Protocol).
    📖 الكتاب بيزوّد: Multiplexing / Demultiplexing باستخدام port numbers (تجميع داتا من تطبيقات كتير في header واحد وإرسالها، والعكس عند المستقبل). الـ error correction بتتم بـ إعادة الإرسال (retransmission). وطريقتين للـ flow control: Stop-and-wait و Sliding Window.
    TCPUDP
    📖 النوعConnection-orientedConnectionless
    📖 الموثوقيةتسليم موثوق + flow control + error control + multiplexingأسرع، لكن مفيش ضمان للتسليم

    Address and Best Path · PDU = Packets

    • Logical addressing (الـ IP address): بتدير عناوين الأجهزة وبتتابع مكانها على الشبكة.
    • Best path determination (routing): بتختار أحسن مسار من المصدر للوجهة حسب ظروف الشبكة وأولوية الخدمة وعوامل تانية.
    • الـ Routers هي أجهزة الـ network layer، وبتقدّم خدمات الـ routing جوه الـ internetwork.
    • بروتوكولاتها: IP و IPv6.
    📖 الكتاب بيزوّد: Gateways (بتوصّل شبكات بـ protocols مختلفة وبتعمل protocol conversion)، وRouting protocols: RIP · OSPF · BGP.

    ⚖️ Transport ضد Data Link — أهم فخ في المحاضرة

    Transport = end-to-end (من الجهاز المصدر للجهاز الوجهة كله).   Data Link = hop-by-hop (خطوة بخطوة على لينك واحد، بين جهازين متجاورين).

    🎯 تدريب: Transport ولا Network؟

    الطبقات 2 · 1 ⭐

    Data Link و Physical: الإطارات والـ bits والأسلاك. (⏱️ ٧ دقايق)

    Access to Media · PDU = Frames

    • مسؤولة عن نقل موثوق للـ frames من غير أخطاء (error-free transfer of data frames) عبر لينك فيزيائي خطوة بخطوة (hop by hop).
    • بتحدد صيغة الداتا على الشبكة (format).
    • بتحوّل الـ raw bit stream من الـ Physical لـ frames.
    • بتضيف header وtrailer للـ frame. الـ header فيه عنوان الـ hardware للوجهة والمصدر.
    • بتاخد قرارات بناءً على العناوين الفيزيائية (غالباً MAC addresses).
    📖 الكتاب: بتتقسم لـ sub-layerين: LLC (Logical Link Control): بتدير الـ error detection والـ flow control وبتتعامل مع الـ network layer. و MAC (Media Access Control): بتتحكم في الوصول للوسط المشترك وتمنع الـ collisions.

    Binary Transmission · PDU = Bits

    • الوظيفة الأساسية: تنقل الـ bits الفردية من node لـ node تاني.
    • هي الـ physical media اللي الداتا (إشارات إلكترونية) بتتبعت فيها من الـ source host للـ destination host.
    • بتحدد transmission mode: SimplexHalf-duplexFull-duplex بين الجهازين.
    • أمثلة: UTPCoaxial (like cable TV)Fiber optic
    📖 الكتاب بيزوّد: بتحوّل الداتا لإشارات (encoding) وترجّعها (decoding)، وبتستخدم modulation / demodulation. بروتوكولات: DSL (ADSL, VDSL) · IEEE 802.11 PHY (Wi-Fi) · Bluetooth PHY (IEEE 802.15.1). وأمثلة الـ simplex: Keyboard, Traditional Monitors.

    تفاصيل الـ simplex / half / full duplex هتتشرح في Lecture 3.

    الـ Transport بتهتم بالمصدر والوجهة النهائيين بس، والـ Data Link بتهتم بكل لينك لوحده.

    الـ Service و Protocol و Interface 🤝

    تلات كلمات بتتلخبط. افهم الفرق ومين بيتكلم مع مين. (⏱️ ٥ دقايق)

    3 عناصر لازم تتوحّد في كل layer (سلايد 11–12)

    📜Protocol specificationاضغط
    كيانين (entities) في نفس الـ layer في نظامين مختلفين بيتعاونوا بواسطة protocol. لأن النظامين open ومختلفين، لازم الـ protocol يتحدد بدقة: format الـ PDUs، وsemantics كل الحقول، والتسلسل المسموح للـ PDUs.
    🛎️Service definitionاضغط
    إيه الخدمات اللي كل layer بتقدّمها للـ layer اللي فوقها؟ وصف وظيفي بيحدد إيه الخدمة مش إزاي بتتنفذ.
    📍Addressingاضغط
    كل layer بتقدّم خدمات لكيانات الـ layer الأعلى، والكيانات دي بتتحدد بـ service access point (SAP). مثال: الـ NSAP بيحدد transport entity بتستخدم خدمة الـ network.

    🖼️ الفرق بالرسم (زي سلايد 13 و 14)

    • Protocol (خط متقطع): الكلام الأفقي بين نفس الـ layer في الجهازين. اتفاق بين الأطراف على إزاي الاتصال هيمشي.
    • Service: اللي layer k بتقدّمه للـ layer k+1 (رأسي).
    • Interface: بين كل layer ولاصقتها (رأسي). بيحدد أنهي primitive operations وخدمات الـ layer التحتانية بتقدمها للفوقانية.

    ↔️ الاتصال الافتراضي ضد الفعلي

    في الحقيقة مفيش داتا بتتنقل مباشرة من layer n في جهاز لـ layer n في جهاز تاني. كل layer بتمرر الداتا ومعلومات التحكم للـ layer اللي تحتها لحد ما توصل لأقل layer، وتحتها الـ physical medium اللي فيها الاتصال الفعلي. الخط المتقطع = virtual communication، والخط المتصل = physical communication.

    📌 مجموعة الـ layers والـ protocols بتتسمى network architecture. ومواصفات الـ architecture لازم تحتوي معلومات كافية تخلّي المنفّذ يكتب البرنامج أو يبني الـ hardware لكل layer بحيث يطيع الـ protocol الصح.
    🔑 تعريف مهم: "a protocol is an agreement between the communicating parties on how communication is to proceed."
